# 02: 글 작성

**What to build:** 방문자가 로그인 없이 이름, 메시지, 글 비밀번호를 입력해 글을 남기면, 페이지 전체 새로고침 없이 서버의 최신 목록으로 갱신되어 새 글이 맨 위에 보이고 작성 폼이 비워진다. 입력값이 규칙에 맞지 않으면 거부되고 필드별 이유가 표시되며, 입력한 내용은 유지된다. 목록의 각 글은 이름, 메시지(줄바꿈 유지, HTML은 글자 그대로), 한국 시간 작성 시각을 보여 준다. 스펙: `.scratch/guestbook/spec.md`.

**Blocked by:** 01 (빈 방명록 페이지와 개발 기반)

**Status:** ready-for-agent

- [x] 작업 전 저장소에 설치된 Next.js 문서(서버 함수/Server Action, 데이터 변경, revalidate)를 확인했다
- [x] 방명록 모듈에 글 작성 기능이 있고, 결과를 `성공 / 입력값 오류(필드별 이유)`로 돌려준다
- [x] 이름: 앞뒤 공백 제거 후 1~20자, 메시지: 앞뒤 공백 제거 후 1~500자(줄바꿈 허용), 글 비밀번호: 4~64자(공백 제거 안 함)
- [x] 글 비밀번호는 Node 내장 scrypt + 글마다 무작위 salt로 해시해 저장하고, 평문은 저장·로그·응답 어디에도 남지 않는다
- [x] 이후 티켓이 쓸 글 비밀번호 확인(타이밍 안전 비교) 기능이 모듈 안에 있다
- [x] 테스트: 작성한 글이 목록 맨 위에 나타남, 공백이 정리되어 저장됨, 각 필드의 빈 값/길이 초과/길이 미달이 `입력값 오류`이고 아무것도 저장되지 않음
- [x] 작성은 Server Action으로 노출되며, Action은 폼 데이터를 모듈에 넘기고 성공 시 목록을 revalidate하는 얇은 어댑터다
- [x] 작성 폼: 이름·메시지·글 비밀번호 입력칸, 비밀번호는 가려짐, 브라우저에도 같은 길이 제한
- [x] 제출 중에는 버튼이 비활성화된다
- [x] 성공하면 폼이 비워지고 새 글이 깜빡임 없이 맨 위에 나타난다
- [x] 입력값 오류 시 필드별 이유가 표시되고 입력한 내용이 유지된다
- [x] 작성 시각은 Asia/Seoul 기준 `YYYY-MM-DD HH:mm`로 표시된다
- [ ] 개발 서버에서 수동 확인 완료
